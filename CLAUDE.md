# Проект: ex-ante анализ Kalshi mention markets (earnings calls)

- Язык ответов и досье: русский; страйки и цитаты оставлять на английском.
- Любое досье строится с жёстким cutoff (дата-время UTC). Нельзя использовать
  документы, новости, цены рынка и транскрипты, опубликованные после cutoff.
- Транскрипт целевого звонка читать запрещено. Если факт из целевого звонка
  всё же попался, не использовать его, записать в раздел LEAK LOG.
- Ничего не удалять и не перезаписывать в transcripts\ и sa_raw\.
- Не перезаписывать готовые досье: имя dossiers\<TICKER>_<дата звонка>_v<N>.md,
  N следующий по счёту (файл без суффикса считается v1).
- Каждый факт в досье сопровождать ссылкой и датой публикации источника.
- Пароли не вводить.
## Защита от утечек (ex-ante)

- Данные Kalshi: `kalshi_raw\*.json` читать только через `python tools\kalshi_meta.py <TICKER> [--event <EVENT>]`.
  Он возвращает только: ticker, event_ticker, title, yes_sub_title, custom_strike, created_time, open_time,
  rules_primary, rules_secondary. Поля result, last_price*, previous_*, yes/no bid/ask, volume*, open_interest*,
  settlement*, expiration_value и свечи не выводить и не использовать.
- Запрещено печатать содержимое kalshi_raw\*.json, kalshi_dataset.json, kalshi_paths.json целиком
  (cat, Read без среза, print всего объекта). Для прошлых событий тикера (не целевого) тоже только kalshi_meta.py.
- Единственное исключение: поле result в kalshi_dataset.json читать только в шаге эмпирической
  проверки слэш-страйков и только для завершённых событий, не являющихся целевым и не
  позднее cutoff; выводить только отфильтрованные поля (event_ticker, strike, result).
- Веб-поиск: добавлять в запрос `before <дата cutoff>`. Игнорировать все материалы с неизвестной
  или позднейшей cutoff датой публикации. Факт без даты публикации в досье не включается
  (идёт в раздел «Не подтверждено по дате»).
- Дата публикации = дата со страницы/метаданных. Дата только из URL помечается «(по URL)» и считается слабой.
  В конце работы каждый пункт из «Не подтверждено по дате» перепроверяется; подтверждённые переносятся в основные разделы.
- Запрещённые слова в поисковых запросах: "earnings preview", "Q4 results", "Q4 FY<год>",
  "fourth quarter results", "earnings call", "earnings beat", "after earnings", "reported",
  а также даты и названия целевого звонка (дата cutoff в `before <дата cutoff>` допустима).
  Запросы тематические: «<Company> <тема/продукт/партнёр>».
- Материалы после cutoff (сводки результатов, пересказ звонка) не использовать; только запись в LEAK LOG:
  источник, что показано, что проигнорировано.
- Журнал результатов, постмортемы, любые файлы с итогами прошлых прогнозов или результатами рынков
  при ex-ante не читать. Хранить вне папки `earnings`.
