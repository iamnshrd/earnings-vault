# earnings — ex-ante анализ Kalshi mention markets (earnings calls)

Рабочий репозиторий для подготовки к торговле на Kalshi mention-рынках вида
«Скажет ли компания слово X на earnings call». Цель — перед звонком собрать
**ex-ante досье**: какие страйки открыты, как часто и почему эти слова звучали
на прошлых звонках, что говорит руководство в публичных выступлениях, какие риски
у правил разрешения. Прогноз/класс в досье не выдаётся, только факты и наблюдения.
Текущая работа — компания **COST** (Costco), целевой звонок 2026-09-24,
cutoff 2026-09-23T21:00Z.

Язык досье и ответов — русский; страйки и цитаты остаются на английском.
**Главные правила — в [`CLAUDE.md`](CLAUDE.md), читать первым.**

## Жёсткие правила (кратко)

- У каждого досье есть cutoff (дата-время UTC). Нельзя использовать документы,
  новости, цены и транскрипты, опубликованные после него.
- Транскрипт целевого звонка читать **запрещено**. Он лежит в репозитории
  (`transcripts/`, `sa_raw/`), но не открывается. Если факт из него всё же попался —
  не использовать, записать в раздел LEAK LOG досье.
- `kalshi_raw/*.json` читать только через
  `python tools/kalshi_meta.py <TICKER> [--event <EVENT>]` (никаких цен, объёмов, result).
  Единственное исключение — поле `result` в `kalshi_dataset.json` на шаге
  эмпирической проверки слэш-страйков, и только для чужих/прошлых событий,
  закрытых не позже cutoff.
- В `transcripts/` и `sa_raw/` ничего не удалять и не перезаписывать.
- Готовые досье не перезаписывать: `dossiers/<TICKER>_<дата звонка>_v<N>.md`,
  файл без суффикса считается v1, следующий — `_v<N+1>`.
- Каждый факт — со ссылкой и датой публикации источника; без даты — в раздел
  «Не подтверждено по дате». Веб-поиск с `before <дата cutoff>`, без запретных слов
  (см. `CLAUDE.md`).
- Журналы результатов и постмортемы с итогами прошлых прогнозов в репозитории
  не хранить и при ex-ante не читать.

## Структура

| Путь | Что это |
|---|---|
| `CLAUDE.md` | правила проекта (ex-ante, защита от утечек) |
| `.claude/agents/dossier-collector.md` | подагент, собирающий досье (10 шагов) |
| `.claude/commands/dossier.md` | команда `/dossier COST 2026-09-24 [cutoff UTC]` |
| `profiles/` | профили компаний (`_TEMPLATE.yaml`, `COST.yaml`): источники, IR, выступления руководства, `same_quarter_calls` |
| `dossiers/` | готовые досье: `COST_2026-09-24.md` (v1), `COST_2026-09-24_v2.md` |
| `tools/kalshi_meta.py` | безопасное чтение метаданных Kalshi-рынков |
| `transcripts/`, `sa_raw/` | транскрипты звонков (discountingcashflows / stockanalysis.com), только чтение |
| `kalshi_raw/`, `kalshi_dataset.json`, `kalshi_paths.json` | история Kalshi-рынков; целиком не печатать |
| `companies.json`, `manifest.json`, `sa_index.json`, `fetch_log.*` | списки компаний и журналы загрузок |
| `collect_kalshi.py`, `build_dataset.py`, `build_paths.py`, `kalshi_client.py` | сбор и сжатие истории Kalshi |
| `fetch_sa.py`, `fetch_transcripts.py/.mjs`, `fetch_earningscall.py` | загрузчики транскриптов |

Скрипты сбора данных писались под Windows (`.venv\Scripts\python`); из облака сети
до Kalshi нет, поэтому данные в репозитории — готовая выгрузка.
`.venv` и `__pycache__` в репозиторий не входят.

## Как работать

1. Прочитать `CLAUDE.md` и профиль компании (`profiles/<TICKER>.yaml`).
2. Запустить `/dossier <TICKER> <дата звонка> [cutoff UTC]` — подагент соберёт
   досье в новый файл `dossiers/<TICKER>_<дата>_v<N>.md`.
3. Проверить разделы «Не подтверждено по дате», «Недоступные источники», LEAK LOG.

Для нового тикера скопировать `profiles/_TEMPLATE.yaml` в `profiles/<TICKER>.yaml`
и заполнить.
